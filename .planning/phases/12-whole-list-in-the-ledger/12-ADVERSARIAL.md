## MAJOR

**M1. The catalog is the evidence for R1/R3 and nothing in PR CI ties it to the core.** `grep catalog tests scripts` shows `catalog.tsv` consumed only by `update` mode, `library.cmake` and the generator's own temporary outputs; the only table check is the first-line pin in `cartdb.inc`. D7 says "retiring a token needs a slot-table edit, regenerated `cartdb.inc`, a core board ... all in the diff", but that is a convention, not enforcement: a PR can hand-edit three data files (`catalog.tsv` status, `reasons.txt`, the ledger) and pass R1 and R3, and `compat.whole_list.reason` only checks the catalog against itself ("board-0 lines are unsupported", both from the same file). Fix (applied): `compat.whole_list.reason` also ties every sms/gg catalog line to `src/cartdb.inc` by SHA-1: machine and board name must equal the fact's (one awk; I ran it today: 1,656 lines, 0 differences), so `unsupported` is exactly "the core table says board 0" and retirement cannot happen without a table change; the pin-derived `skipped` statuses can only be tied to `pin-counts.txt` (a hand-edit must also edit it), and D7 now says so plainly instead of claiming a guard.

**M2. R2 and R3 contradict, and R2 deadlocks a legitimate pin bump.** R2 ("every id in the base ledger is in the head ledger") has no exception, yet R3 lets a base `skipped` row "vanish" when its catalog status changes; a compound entry that leaves the list (pin bump) vanishes by id and R2 refuses it, and the allow list can only name `pass` rows. The only escape would be editing the judge, which the base judge forbids. Fix (applied): R2 protects information-bearing rows only: a base row whose status is `fail`, `unsupported` or `skipped` keeps its id in the head ledger unless R3 releases it; `unknown` rows may vanish (the head tests, not the ratchet, guard the denominator).

**M3. The new judge reads data by cwd and fails open or breaks callers.** `library.sh` runs `compat-ratchet.sh` from whatever directory the owner is in and passes `COMPAT_CATALOG` only as a one-command prefix to `update` (`library.sh:58`); the library tests run it from the ctest working directory with a synthetic catalog. With D6's cwd-relative defaults, R1/R3 would read no file or the wrong catalog; nothing says whether a missing file fails closed. Fix (applied): ratchet mode exits 2 when the catalog or `reasons.txt` is unreadable (negative control added); `library.sh` exports absolute `COMPAT_CATALOG` and `COMPAT_REASONS` for every call and the library and ratchet tests run with `WORKING_DIRECTORY` set to the root or with stand-ins.

**M4. LEDG-05 overrides an owner scope decision and the plan does not say so where the owner will look.** `REQUIREMENTS.md:8` records "the `is_experimental` exit is a command over the rows the owner's local library judged" (2026-11-10). D10/D12 amend LEDG-05 and the ROADMAP but never amend line 8, and D10's "(rules 6 ... precedent)" is not a rule requirement: rule 6 explicitly allows an owner run on their own hardware, so this is a sequencing choice (Phase 11 says so itself, `11-CONTEXT.md:100`). PROJECT.md:24 and SEED-001 support dropping the flag once the ledger covers the lists, so the choice is defensible; the defect is visibility and wording: the floors of the exit command (9 fixture passes, 1 PAL, 2 FM) are fixture values, so the legs that touch the flag are not about the owner's rows and the command should not be described as the gate. Fix (applied): amend line 8 with the same text; say in the requirement, the PR body and the owner's batched ask that the flag left on public evidence (`policy.claims_scoped` plus `compat.exit`), that the owner's run follows, and that restoring the flag is a one-line revert the owner may ask for; the `exit:` block prints `owner_rows=none` until a library run has merged.

## MINOR

1. **Claims guard false positive on today's README.** The digit rule `[0-9].{0,12}(games|titles|...)` matches `README.md:75` ("3-D glasses titles"), so D11's positive control ("the current files pass") fails on first run. Fix: the digit must be a whole number token followed by a space: `[0-9][0-9,]*[ ]+([a-z]+[ ]+){0,2}(games|titles|cartridges|carts)`. Residual: the guard is a literal tripwire (a rewording passes), stated in the docs sentence.
2. **Unguarded count claims.** README "most catalogued titles have no checked result" and the generated intro "Most rows are unknown" become false after the owner's run, and nothing checks them. Fix: word them without "most" ("a title with no checked result is listed unknown").
3. **Row-cap arithmetic wrong, decision stands.** D6's "worst case 2,104" ignores the `update` whitelist (3 rows per SMS identity, 2 per GG: 641 x 3 + 822 x 2 = 3,567, about 3,600 with devices and fixtures, 88 percent of the old 4,096). 8,192 is justified, but by 2.3 times headroom, not 3.9. The insertion sort is quadratic on unsorted input: BWK reverse-ordered 1,472 / 4,000 / 8,000 rows took 0.5 / 3.2 / 12.2 s; sorted input is linear. Fix: state both.
4. **Live-parse accounting misses `compat.migration`.** `migration.cmake:243-250` normalizes the live ledger three times, so "at most 6 live parses per lane" is about 13. At 0.15-0.3 s native it is harmless, but the claim and the plan 2 list are wrong. Fix: the migration live leg reads the header and one normalize; accounting "at most 8".
5. **Plan 2 cannot seed.** D13 has plan 2 build `library.synthetic`'s stand-in with the seed (D8), but `compat-seed.sh` arrives in plan 5 and D8 in plan 6. Fix: plan 2 uses the fixture extract plus the Crazy Faces row (literal); plan 6 switches to the seed; between plans 5 and 6 the library test still copies a stand-in, not the live ledger.
6. **`update` with a status-less catalog.** Existing synthetic catalogs have five fields; "discard a candidate whose catalog status is not `unknown`" must read a missing field as `unknown` or every library test breaks.
7. **Generator `<list>` source unspecified.** The compound id needs the list name; nothing says it comes from `<softwarelist name="...">`, and every synthetic XML in `generator.cmake` has none. Fix: take the root `name` attribute; a compound record under an unnamed list exits 1.
8. **D12 vs D9.** The LEDG-04 amendment says "every `fail` row" but D9 caps `fail` rows at 40.
9. **`compat-seed.sh` as `operation`.** Its stated saving (about 20 counted lines) is the reclassification D14 forbids for checks. It stays `operation` only because it writes and never judges (`compat.whole_list.fresh` asserts its output); the classification reason must say that and must not copy "never fails on repository content" (it exits 1 on a stray id).
10. **Stale comment.** `src/state.c:34` names "behaviour revision 16" and `tests/cart/test_cartdb.c:22,208` hard-code 20 slots; add to plan 1.
11. **Over-scope.** The `maintaining.md` "CI speed" rewrite (D15), optional SEED-009 `scan:` and `.gitattributes` are not LEDG work; cut the first to a seed (docs bytes, plan 9 and a review surface), keep `.gitattributes` (one line) and the `scan:` only if it fits.
