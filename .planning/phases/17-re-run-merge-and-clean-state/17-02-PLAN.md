<objective>
Give a maintainer one script that checks the repository is in a clean state before a milestone-close pull request
(TUNE-17): open pull requests, `CI required` on the head of `main`, the latest release against the manifest with no draft
and a green tag, no stuck release pull request, a clean work tree on `main`, and no releasable commit waiting for
release-please. A small fake-`gh` test with a dirty-tree control proves the exit statuses, and the maintainer docs say how
to use it.

Purpose: milestone close has twice relied on remembering these checks; one script makes the state visible.
Output: `scripts/milestone-close.sh`, `policy.milestone_close`, a classification row, two inventory lines, one docs paragraph.

Executor rules (CLAUDE.md): POSIX sh, `set -eu`, small and self-contained; no planning IDs in code, test names or docs; the
script is a check to run, never a release gate, and never runs in CI (rule 8). Acceptance asserts exit status and tolerant
regexes. Nothing is pushed in this plan (plan 03 pushes once for plans 01 and 02). Do not edit `.planning/STATE.md`
in this plan: the single rule-9 Runtime Log row for each execute step is written by plans 03 and 04 only. This plan runs after plan 01 (wave 2), so it never shares the `build/ci`
tree with it and edits `docs/maintaining.md` only after plan 01's `docs.budgets` run. Never run `/gsd-next` or any command
with `--auto` or `--chain`, and never set a `COGMASTER_ALLOW_*` variable.

Rule 11 exception, stated once: the live run in Task 3 must execute the script with a worktree of `main` as its working
directory, because the script's interface is "run from a checkout of `main`": its `git status`, `git symbolic-ref` and
`git rev-parse` and `gh repo view` all read the working directory's repository, and no git or POSIX flag points all of
them elsewhere (`env -C` is not POSIX and is missing on macOS). The directory change happens inside one child shell
(`sh -c 'cd "$1" && exec sh "$2"'`); the agent's own shell stays at the repository root, the command is recorded from
there, and every other command in this plan uses `git -C` or a path instead of a directory change.
</objective>
