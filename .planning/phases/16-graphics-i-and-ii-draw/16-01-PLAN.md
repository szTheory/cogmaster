## Decisions taken in this plan (with reasons)

- **Lane placement (research Open Question 5, D-28, D-29; CLAUDE.md rule 5):** all nine rider tests go in the ci lane, in
  `tests/policy/tooling_cases.cmake` included from `tests/policy/tests.cmake`, so `cmake --workflow --preset ci` runs them;
  rule 5 has no hygiene exception. The earlier reason for the hygiene lane (files disjoint from plan 02) is gone: the plans
  run strictly in sequence, and plan 02 edits the same two inventories after this plan. Checked against the tree:
  `COGMASTER_SH` is found only when `COGMASTER_HYGIENE` is on (CMakeLists.txt lines 184-200), so the new file finds its own
  shell with `find_program(tooling_sh sh REQUIRED)`, as `tests/tests.cmake` does for the library lane (`library_sh`), and
  uses `${GIT_EXECUTABLE}` from the `find_package(Git REQUIRED)` already in `tests/policy/tests.cmake`. The ci lane already
  runs `sh scripts/library.sh run` and git on every leg, Windows included (`library.synthetic`, timed on windows-arm64 in
  run 43158408243) and on wasm32 (`library.diagnose*` are in `wasm32.txt`), so no guard is needed. A `NOT WIN32` guard would
  be wrong here: `ci-msvc` uses `tests/inventory/ci.txt` and configure's inventory check (`cmake/CogmasterTests.cmake`)
  requires the registered names to equal that file exactly, so a guarded registration fails configure on both Windows
  legs. The wasm32 preset has its own inventory but registers `tests/policy/tests.cmake` in full (47 `policy.` lines in
  each inventory at HEAD), so the nine names go in `wasm32.txt` too; they run on the Linux host and use no wasm binary.
  `quality.json` holds floors (`tests.ci` 669, `tests.wasm32` 627), so nine more lines break nothing.
- **Windows portability of the controls:** every byte a shell reads is written with `file(CONFIGURE ... NEWLINE_STYLE UNIX)`
  or by the shell (never `file(WRITE)`, which writes CRLF on Windows), as `firmware_window_cases.cmake` does; the fake
  `curl` is made executable with `file(CHMOD ...)` and found through `cd "$1" && PATH="$PWD/shim:$PATH"`, so the PATH entry
  is in the shell's own path form (a `C:/...` entry would split at its colon in an MSYS PATH); `file://` URLs use the
  `file:///` form for a drive-letter path, as `fixtures.wla_pin.self_test` does; timeouts are 30 s, since a refused
  connection to 127.0.0.1 takes about 2 s per attempt on Windows. If, after triage (CLAUDE.md rule 8: a failing harness
  assertion is a test bug first), a hosted leg still cannot run one group for a platform reason, the group stays in the ci lane:
  fix the test or narrow the platform-dependent assertion; never a platform guard on a ci-inventory registration. A true
  platform blocker that cannot be fixed that way goes to the owner with the rule 5 conflict stated, not a silent lane move. Hosted legs first run these tests at plan 03's draft push.
- **Budget guard (research Open Question 4, D-30):** not needed. `scripts/library.sh` is `operation`, `cmake/WlaDx.cmake` and `scripts/fetch-pin.sh` are `build`, and `tests/policy` is outside the counted globs. The plan still measures before and after with `budgets.cmake` and does not raise the cap.
- **Attempt count in the final message:** the FATAL_ERROR text carries `after attempt N of 3`, so one regex proves both that a permanent failure fails and that it did not retry, with no negative regex.
