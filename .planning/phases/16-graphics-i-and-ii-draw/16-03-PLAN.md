## Decisions taken in this plan (with reasons)

- **Runner and library seeds (research Pitfall 1, corrected):** `mode0.sms` (runner) changes R1 `$40` to `$50` (nibble 1,
  `vdpmode=text`); `mode2.sms` changes R0 `$02` to `$00` and R1 `$40` to `$48` (nibble 4, `vdpmode=multicolor`). Research
  proposed R1 `$48` alone for `mode2.sms`, but with R0 = 2 that is nibble 6 (`mixed`); both forms keep the byte counts and
  `want_checked 11`. The `trace_fault` image changes R1 `$40` to `$50`. The library `CASE=main` `mode0.sms`, which research
  wrongly called canned, gets the same R1 `$50` change and its group line expectation follows. These land before the
  renderer because text and multicolour fault in both trees, so each commit is green and the renderer commit touches only
  the tests D-25 names.
- **What stays with the renderer (D-25):** `vdp.background.unsupported` and `fault_run` in `tests/ports/test_gun.c` change in
  plan 04's renderer commit, as D-25 says; their expectations flip in that commit.
- **Planner sweep (B-1 re-sweep, recorded so the executor can re-run it):** `grep -rn -e unsupported_video_mode -e UNSUPPORTED_VIDEO_MODE -e 'vdpmode=' tests`
  lists the fault expectations; besides the four seeds above and the two D-25 tests, it finds only `tests/runner/test_runner.c`
  (the diagnose word table, no core run), `tests/api/v4.c` (the constant's value) and canned lines in
  `tests/library/diagnose.cmake` (no core run). The display-on register seeds in C tests (`tests/bus/test_vdp.c`,
  `tests/vdp/test_sprites.c`, `tests/vdp/test_background.c` `make_profile`, `tests/ports/test_state.c`) all set R0 bit 2
  (mode 4), and `tests/fuzz/seeds.c` `static_display` is mode 4. Plan 04 runs the whole ci lane on the renderer commit, so
  anything this sweep missed fails there by name.
