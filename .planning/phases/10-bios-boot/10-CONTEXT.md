## Resolved conflicts (decision, evidence, reason)

1. **Scope: one 8 KiB Master System BIOS; the Game Gear BIOS is a seed.** Decision: `cogmaster_load` accepts a BIOS of exactly 8,192 bytes on `COGMASTER_MACHINE_SMS1` or `SMS2` (any region, any TV) with a cartridge image, and nothing else. A Game Gear machine with a BIOS is `ERR_PROFILE_REJECTED`; any other size (0 aside) is `ERR_UNSUPPORTED_SIZE`; no image is `ERR_NO_CONTENT`. The runner recognises all 13 digests of ASSET_POLICY section 4 and names the ones it does not run ("recognised, not supported yet": the 1,024 byte Game Gear dump, the 16,384 byte Store Display, the six 131,072/262,144 byte built-in-game dumps). The libretro `.info` declares exactly three optional firmware rows, `bios_U.sms`, `bios_E.sms`, `bios_J.sms`; it does not declare `bios.gg`. The `$3E` b6-on-Game-Gear fix (`bus.c:114-118` takes the cartridge off on a Game Gear, hardware, MAME and ares ignore b6 there) is NOT made in this phase. Evidence: smstech and MAME agree a Game Gear BIOS window exists at `$0000-$03FF` with b3, but no held source says in which mode a real Majesco BIOS writes `$3E` (hardware lens open question 4; architecture open question 1), the native decode would add a latch for every shipped Game Gear title (`io.c:170`, `state.c:375` bounds it to `[$A8,$A8]`), and a self-authored 1 KiB image can only prove our own model. The b6 fix changes behaviour for Game Gear carts running in SMS mode that set b6, so it needs `tests/io` and the ledger to be checked for movement, and no BIOS-03 or BIOS-05 criterion needs it. Reason: smallest scope that satisfies BIOS-01 to BIOS-05 for the machines that can be tested; DEC.62's four names stay the names (the seed adds `bios.gg` and its `.info` row together with the code that reads it, because every `.info` claim maps to a test). If the seed lands, the stated way to keep every hash and fault count unchanged is: the Game Gear `$3E` latch exists only when a BIOS is attached (fast boot and every existing test keep `$A8` and the unmapped-write fault), and the b6 change goes behind its own test with `git diff --quiet origin/main -- tests/io` and the library ledger as the movement check; if anything moves, the doc is amended, not the test.
2. **Arbitration (BIOS-05): by machine, written once as a closed form.** Decision: a read at slot-area address `a < $C000` with `bios_on = (bios attached && !(c & $08) && a < $2000)` and `cart_on = !(c & $40)` returns: SMS1 (any region): cartridge if `cart_on`, else BIOS if `bios_on`, else undriven; SMS2: BIOS AND cartridge if both, the one that is on if one, else undriven. Undriven is exactly today's behaviour (the empty-slot bookkeeping rule below aside; open bus: retained byte on SMS1, `$FF` pull-up on SMS2, `UNMAPPED_READ` fault, `open_bus_reads`). `$3E` b7 and b5 change no read VALUE (no expansion or card device exists). They have exactly one effect, and only with a BIOS attached: an undriven slot-area read (cartridge off, BIOS off) with b5 or b7 clear (a card or expansion slot enabled but empty) returns the same open-bus value but records no fault and does not bump `open_bus_reads`; with b5 = b7 = 1, or with no BIOS attached, it is today's `UNMAPPED_READ`. Reason (decided, not left open): a real BIOS "disables the BIOS ROM and enables card, cartridge and expansion in turn" and "tries card, then cartridge, then expansion" (SMS-SYSTEM section 3 and the boot flow, [SYS.04]), and `cogmaster__fault_record` keeps the first fault for the whole run (`src/fault.c:7`), so without this rule `--trace first-fault` would stop inside the BIOS on a probe and mask the game's own first fault. It lives in the cold `mem_read_slow` path (zero hot cost), is a labelled model row (no measurement of what the probe reads), and fast boot is untouched. RAM (b4) and the I/O chip (b2) are unchanged. A BIOS-only-on read at `$2000-$BFFF` is undriven: this is a model choice with no hardware measurement (ares mirrors the 8 KiB, MAME reads a zero-filled region, the hardware lens says nothing real depends on it), the test asserts it as a labelled model row and the doc says so. A write reaches the cartridge mapper only when `cart_on` and nowhere otherwise (`bus_write` and `io_glasses_write` are not touched): a BIOS-only-on write faults `UNMAPPED_WRITE` exactly as a cartridge-off write does today. Power-on `$3E` with a BIOS is `$E0` (expansion, cartridge and card off; RAM, BIOS and I/O on; b1:0 zero): MAME builds exactly this (`sms_m.cpp:880-887`), ares enables only the BIOS, and it is the value forced by "BIOS visible, cartridge hidden"; it is a derived constant, not a measurement, and is labelled so in the code comment, `docs/bios.md` and SMS-SYSTEM. Evidence for the per-machine rule: smstech section 4 (hardware test: SMS "the cartridge has precedence, no data corrupted"; SMS 2 "logically ANDed"), MAME `sms_m.cpp:652-668` (ANDs on every non-Game-Gear machine, so wrong for SMS1) and ares `cpu/memory.cpp` (cartridge overrides on every model, so wrong for SMS2); the research text "exclusive overlay, BIOS wins at its window" is the third wrong answer. The Japanese console is the `machine` the user selects (SMS1 or SMS2), region never picks the rule. A real BIOS never leaves both on (it copies itself to RAM, disables itself, then enables the cartridge), so the combination is reachable only by a hostile or test image: a bounded-behaviour and fuzz matter. **Hot path:** a derived `uint8_t mem_slow` in `struct cogmaster` equals `(c & $50) != 0 || (bios.size != 0 && !(c & $08))`, so `mem_read` (the hot path) replaces its masked test by a load and a test of the flag (the same instruction count expected: zero added, measured, not assumed), and ONLY `mem_read` consults the flag. `mem_read_slow` and `cogmaster_peek` share one decoder `mem_slow_driven(m, a, &v)` that decodes from `io.mem_ctrl` and `bios.size` directly and never reads `mem_slow` (peek is cold). This is required by `tests/core/test_core.c:1514-1516`, which writes `m->io.mem_ctrl |= $50` directly and asserts `cogmaster_peek` at `$0400` and `$C000` is `$FF`: a decoder that trusted a flag only `bus_decode` refreshes would return driven data there and put `core.peek` red; with the rule above that test stays byte-equal and valid, and `bios.slow_flag` still compares the flag itself. (`tests/ports/test_glasses.c:305` also writes `mem_ctrl` directly but only calls `bus_write`, which does not read the flag, so it is safe.) With no BIOS attached the flag equals the old mask test bit for bit, so no hash moves. `cogmaster__bus_decode(m)` recomputes it at exactly four sites: the `$3E` write in `io_out`, the end of `io_reset` (both land in plan 4), `boot_power_on` and after APPLY in `state_load` (both land in plan 5, so the `bios.slow_flag` legs for load, power and soft reset and state load are added in plan 5, not 4). Placement: `mem_slow` sits next to `io` (what `mem_read` already touches) and `bios` after every hot member. Perf procedure: a branch dispatch of `ci.yml` and a fresh `ci.yml` dispatch on `main`, `delta_bp = (H - B) * 10000 / B` read from each run's perf job line, at most 100, both run URLs, both `perf control boot_to_play runs=H1,H2,H3 spread=N` lines and the computed `delta_bp` recorded in the plan 5 SUMMARY (expected 0 or negative; the PR run's `perf_compare.cmake`, limit +100 bp, repeats it). Stated remedy if `delta_bp > 100`: move `bios` and `mem_slow` to the end of `struct cogmaster` and re-measure (the struct gains 8 KiB before `ram` and `vdp` otherwise, shifting every hot offset). Rejected: an `(c & $58) != $08` test (two instructions on every access) and a per-machine function-pointer table.
   **Test design (independent closed form):** `bios.arbitration` runs 16 combinations of `$3E` b7, b6, b5, b3 (b4 and b2 clear) on SMS1 and SMS2 with a distinguishable BIOS byte `$F3` and cartridge byte `$0F` (AND `$03` differs from both), probing `cogmaster_peek` and `cogmaster__bus_read` (fault counts) at `$0000`, `$1FFF`, `$2000` and `$C000`. ## Risks and what a reviewer should attack
- A stale `mem_slow` is the one new way to be silently wrong: attack the four recompute sites (the `$3E` write, `io_reset`, `boot_power_on`, APPLY in `state_load`), a state saved with b3 clear loaded into a BIOS instance, `$3E` writes at every instruction under a hostile image, and `cogmaster_peek` against `mem_read`.
- The arbitration is one hardware test per machine (smstech); MAME and ares differ. Attack the SMS1 cartridge-precedence row, the undriven `$2000-$BFFF` model row, `$3E` b7 and b5 acting on nothing, and that "both on" is reachable only by a hostile or test image.
- The equivalence check can be vacuous: the image writes what `boot.c` writes. Attack the classification-complete lists (a new state field must fail the test until classified), the pinned counts, the independence literals, the mutation loop and that a bad image fails by name; accept the honest limit, which is stated.
- The scans can pass because they saw nothing or leak what they saw. Attack the vacuous guards, `EXTRA_DIGESTS` (it may only add; grep the scan for `getenv` and `ENV{`), the manifest (a manifest row is scanned, not exempt), a scan output that prints a window, an offset or a path (the anchored regexes), a hex copy of a dump in a temp file, the Windows `file(WRITE)` newline translation in controls, and `od`/`awk` differences (the window scan runs in the local `library` preset and the hooks; its controls run in the Linux `hygiene` lane only, never on a `ci` leg, macOS, Windows or wasm32; the release scan is pure CMake on every leg), the release scan's scope (a staging directory of the leg's three zips, never the build tree, whose own seed is in the copier-header class), and an `od`/`awk` control that passes because the file it names was not read).
- Legal: no BIOS byte or reconstruction anywhere. Attack any byte-derived constant (an address, an offset, a string from a disassembly) in a comment, test or doc; a CRC32 plus a size plus a partial window "for faster matching" (rejected); the image's owned marker (not `TMR SEGA`); `byte_run`'s honest limit; any real-BIOS frame, state, RAM or hash in the repo, a CI upload or a log (the only digest printed is the SHA-1 fact); recognition becoming trust (it changes only the label).
