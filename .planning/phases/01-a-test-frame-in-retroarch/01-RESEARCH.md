### Locked Decisions

#### What lands in phase 1 beyond FRAME-01..09
Rule: a surface lands in the phase whose subsystem first gives it data that a test can falsify (muhtari's
"a status enters the exit table when the runner first returns it", applied to options and API).

- **D-01:** State visitor, phase 1, **internal only**. `src/state.c` runs SIZE, WRITE, VALIDATE, APPLY and
  RECORD over what a test-card instance holds: a fixed header (magic, format version, header size, total size,
  behaviour revision, API version, packed profile, ROM CRC-32 = 0 with no content, body CRC-32, frame, ticks),
  the profile, frame and tick counters, the ARCHITECTURE §8 counters, and the fault record. Byte-wise LE,
  `_Static_assert` tripwires. Tests (every leg, including `be32` and `wasm32`): save → load → save is
  byte-equal; the RECORD sweep rejects each field out of range plus bad magic, size and CRC, with the instance
  unchanged after each rejection. No public `cogmaster_state_size/save_state/load_state` and
  `retro_serialize_size` returns 0 until the state requirement (STATE-01) adds them. Capped at one plan; overflow
  becomes a seed, not a gap. — **Reversibility:** reversible — adding the public entry points later is an
  API_VERSION bump only.
- **D-02:** First-fault record, phase 1 for the struct, recorder and getter. `cogmaster_fault` is in the header
  as in ARCHITECTURE §4 (size-tagged); an internal `fault_record()` keeps the first fault only; `reset` clears it;
  the visitor saves it; `cogmaster_get_fault` returns `present = 0` after create and `ERR_STRUCT_SIZE` for a
  too-small struct. Unit tests drive the internal recorder (first wins, reset clears, survives the state round
  trip). Nothing calls the recorder yet; phase 2 adds the call sites and the runner's `--trace first-fault` line
  (CPU-05).
- **D-03:** Runner surface in phase 1: no cartridge → test card, `--machine auto|sms|gg`, `--frames N`,
  `--hash` (prints the hash of the last frame's crop), `--png N:FILE` (for the RetroArch compare), `--bench`
  (FRAME-09), `--help`, `--version`. The exit table contains only statuses phase 1 actually returns (0, 1, 2).
- **D-04:** `--probe` and `--trace first-fault` → phase 2 (CPU-05). `--region` → phase 2 (observable via
  ports, CPU-04; PAL+GG and PAL+JAPAN exit 77 then).
- **D-05:** `--expect FILE` (exit 3) → phase 3, when many fixture hashes are pinned. Phase 1's two hashes are
  CTest `PASS_REGULAR_EXPRESSION` checks, with a `WILL_FAIL` negative control using a wrong hash.
- **D-06:** `--port1/--port2` and `--input FILE` → phase 3 (GAME-04). The `--input` format is exactly the body
  line of the v3 movie format (one line per frame, absolute button states per port); v3 only prepends a header.
- **D-07:** `--hash-audio` → phase 4 (SND-03).
- **D-08:** `--capabilities` → v3.0 (its only reader is Playstead's continuation `qualify`); `--boot/--bios`
  → v2.0 (LIB-03, ARCHITECTURE §9). HOSTS-AND-INTEGRATION §4's table was corrected in this step to match; that
  is a docs consistency fix, not a reopened decision.

#### Public header breadth
- **D-09:** The header grows by phase. A function, field, enum constant or status enters the header in the
  same commit as the code that gives it real behaviour and a test that `ci` runs. No stubs, no
  reserved-but-rejected constants, never a generic NOT_IMPLEMENTED status. — **Reversibility:** costly — once
  released, every declaration is append-only.
- **D-10:** Phase-1 header contents:
  - Macros: `COGMASTER_VERSION_MAJOR/MINOR/PATCH` (generated by `configure_file` from `version.txt`),
    `COGMASTER_API_VERSION 1`, `COGMASTER_ABI_VERSION 1` (SOVERSION = ABI number, not the 0.x major),
    `COGMASTER_BEHAVIOUR_REVISION 1`, `COGMASTER_STATE_FORMAT_VERSION 1`.
  - Status (`typedef uint32_t cogmaster_status`, explicit values, append-only): `OK = 0`, `ERR_ARGUMENT`,
    `ERR_STRUCT_SIZE`, `ERR_NO_MEMORY`, `ERR_BUFFER_TOO_SMALL`, `ERR_NO_CONTENT`, `ERR_PROFILE_REJECTED`.
    (State statuses arrive with the public state API.)
  - Types: opaque `cogmaster`; `cogmaster_allocator` {alloc, free with size, user}; `cogmaster_config` {size,
    allocator}; `cogmaster_versions` {size, library x/y/z, api, abi, behaviour, state}; `cogmaster_media`
    {size, image, image_size, machine} (image NULL and size 0 → test card); `cogmaster_info` {size, machine,
    crop w/h, field w/h, max w/h, fps num/den, PAR num/den}; `cogmaster_frame` as in ARCHITECTURE §4;
    `cogmaster_run_result` {size, stop, overshoot_ticks}; `cogmaster_fault` as in ARCHITECTURE §4.
  - Enums as `uint32_t`, 0 = default in every input field: machine `AUTO = 0` (→ SMS2 in phase 1), `SMS2`,
    `GG`; reset `SOFT`, `POWER`; stop `FRAME`; frame flag `FULL_FIELD`. Later values append in arrival order;
    the ARCHITECTURE §10 seams stay as `switch` cases in `src/`, not header constants.
  - Functions (9): `get_versions`, `create`, `destroy` (NULL-safe), `load`, `reset`, `run_frame`, `get_frame`,
    `get_info`, `get_fault`.
  - Later: `set_input`, `probe`, `peek`, `poke`, `get_z80`, `get_counters`, `get_memory` (phase 2);
    `get_vdp`, battery span, `save_generation` (phase 3); `get_audio` and the config's audio rate (phase 4);
    public state API (STATE-01); `set_hooks`, `run`, budget (v5).
- **D-11:** Size-tag rule, made precise (ARCHITECTURE §4 row amended in this step): input structs below their
  *first released* size → `ERR_STRUCT_SIZE`; between first released and current size → missing fields default
  to zero; larger → accepted only if the extra bytes are zero. Output structs: the library writes
  min(size, its own sizeof). One unit test passes each input struct at its first-released size. Without this,
  every appended field would break older callers and no CI consumer would notice.
- **D-12:** `COGMASTER_API_VERSION` +1 in each release whose header gained a declaration (the phase's first
  header-adding plan bumps it). ABI/SOVERSION changes only when a released signature, layout or value changes:
  a `feat!` with a written reason.
- **D-13:** libretro adapter in phase 1: `input_poll` called and the result dropped; `av_info` reports the NTSC
  rate 1,640,625/27,379 and a fixed 48,000 Hz sample rate until phase 4; the adapter emits silence of the exact
  rational per-frame length or none (planner's choice, tested either way); `retro_get_memory_size` returns 0;
  `retro_serialize_size` returns 0.
- **D-14:** One terse line per declaration in the header; behaviour prose in `docs/` (FRAME-04 checks 24 KB).

#### Test card
- **D-15:** Static card, drawn in software by a pure integer function of (x, y, machine) into the real 256×192
  field, then cropped and hashed; never through the VDP or CRAM model. The only code shared with the future VDP is
  the `c | c << 2` SMS colour expansion. Every no-content `run_frame` redraws the same card; phase 3 must keep
  the no-content path on `testcard.c` (the pinned hash test enforces it). — **Reversibility:** costly — the
  pinned hashes and the behaviour revision change if the card changes.
  Colours RGB444 `0000BBBBGGGGRRRR`: WHITE 0x0FFF, BLACK 0x0000 (backdrop), RED 0x000F, GREEN 0x00F0, BLUE
  0x0F00, MAGENTA 0x0F0F. First matching rule wins.
  - **SMS** (crop 0,0,256,192; x 0..255, y 0..191):
    1. `x<8 && y<8` → WHITE (orientation corner).
    2. `x==0 || x==255 || y==0 || y==191` → WHITE (crop-edge frame).
    3. `y<32` → RED.
    4. `y>=161` → GREEN.
    5. `x<64` → `((x^y)&1) ? WHITE : BLACK` (1×1 checker).
    6. `x>=193` → BLUE.
    7. Chart x 64..192, y 32..160: `lx=x-64, ly=y-32`; if `lx%16==0 || ly%16==0` → BLACK; else
       `col=lx>>4, row=ly>>4, r=col&3, g=row&3, b=((row>>2)<<1)|(col>>2)`, `c=b<<4|g<<2|r`, pixel =
       `expand(c)`. That gives 64 swatches of 15×15, each colour once.
  - **GG** (crop 48,24,160,144; `u=x-48, v=y-24`):
    0. Field pixel outside the window → MAGENTA (never hashed; names a wrong crop origin or pitch at once).
    1. `u<8 && v<8` → WHITE.
    2. `u==0 || u==159 || v==0 || v==143` → WHITE.
    3. `v<8` → RED.
    4. `v>=136` → GREEN.
    5. `u<16` → 1×1 checker.
    6. `u>=144` → BLUE.
    7. Chart u 16..143, v 8..135: `cx=(u-16)>>1, cy=(v-8)>>1, r=cx&15, g=cy&15,
       b=((cy>>4)<<2)|(cx>>4)`, pixel `b<<8|g<<4|r`. All 4,096 values once as 2×2 cells.
  - Diagnostics: the corner shows a mirror or flip; red-top/blue-right distinguishes an R/B swap from a flip;
    the white frame and the magenta surround catch crop errors; edge shear catches pitch errors; every nibble
    value catches byte-order errors.
- **D-16:** `--frames 60 --hash` prints the SHA-256 of frame 60's crop (LE uint16 rows); one golden hash per
  machine is pinned as a test constant. Frame advance is shown without moving pixels:
  - the in-process libretro test counts 60 video callbacks;
  - it poisons its copy with 0xA5 before each frame and checks every delivered frame is equal;
  - frame 60 must equal the runner's frame byte for byte;
  - the core's frame counter (runner hash line, or the fault/visitor frame field) reads 60.
- **D-17:** The hosted RetroArch case is SMS only (no content → SMS card). Any N works; use N=60. The
  screenshot is expected at native 256×192 with `video_gpu_screenshot=false`, as muhtari observed (its run
  38971166983); the first hosted run confirms it for this core.
- **D-18:** FRAME-02 wording changed in this step to "GG 160×144 showing all 4,096 RGB444 colours"; the
  ARCHITECTURE §9 test-card bullet was rewritten to match D-15. `docs/` gets an element-by-element explanation
  of the card (as muhtari's runner doc does).

## Project Constraints (from CLAUDE.md)

Directives from `./CLAUDE.md` (= `AGENTS.md`) and `./.claude/CLAUDE.md`, with the authority of locked decisions:

1. **Licence:** MIT/BSD/ISC/zlib/CC0 code may seed a module with its notice; GPL, LGPL, non-commercial and unlicensed emulator source is never opened or kept. Reference emulators run only as released binaries (RetroArch DMG is a frontend binary: fine).
2. **Three deliverables:** library, runner, libretro core. No window, audio-device or input-device code.
3. **Clean tree:** no ROM/BIOS/save bytes except `tests/roms/manifest.txt` fixtures; no personal paths, e-mails or names; noreply commit identity; `scripts/hygiene.sh` on every commit and push.
4. **Deterministic, bounded core:** integer-only; all state in the instance; identical frame/audio hashes on every platform; every call bounded; the core never reads a wall clock.
5. **Tested and documented together:** every behaviour change lands with a test `cmake --workflow --preset ci` runs; README user-facing and short; testing/CI/maintainer docs in `docs/`; public header terse, behaviour prose in `docs/`.
6. **Automation-first verification:** the agent verifies (reads docs vs code, views images, runs RetroArch on hosted CI); ask the owner only for identity-bound consent (App key, admin settings such as applying the ruleset, a merge auto-merge cannot make) or a run on their hardware.
7. **Proportional gates:** repository-check code is CMake `-P` or POSIX sh; real-host RetroArch e2e code < 300 lines in total, **checked by a test**; every gate names the fault it prevents; ≤ 2 review fix rounds, 1 gap round; review before verification; review findings about test/tooling code become seeds.
8. **No invented ceremony:** no attempt quotas, slots, admission/publication ceremonies; requirements never name a fact only a published release can show.
9. **One GSD step per session**; never set `COGMASTER_ALLOW_CHAIN` / `COGMASTER_ALLOW_MAIN_COMMIT`; record runtime and model in STATE.md.
10. **Branch, then PR:** `phase/01-a-test-frame-in-retroarch` (exists locally and on origin); after `/gsd-ship`, Conventional Commit title, `gh pr merge --auto --squash` in a shell, confirm a CI run exists on the head commit; release PR must be green.
11. **Evidence** = command + exit status + run URL, written by the command from the repo root, no `cd` chains.
12. **Pins are public:** pin to commits `gh api repos/<o>/<r>/commits/<sha>` answers 200 for; sibling code fetched with `gh api`, never a local checkout.
13. **Lessons** are hypotheses until reproduced.
- **GSD summaries:** `requirements-completed:` and block-style `coverage:` list (id, description, requirement, verification{kind, ref, status}, human_judgment); no flow style, no inline `#`. Acceptance checks on exit status and tolerant regexes, never a tool's exact output.
- **Style:** small modules, plain control flow, fixed-width ints; public names `cogmaster_`, module-prefixed internals; hardware comments cite a source; **no planning IDs in code, test names or user docs**; ponytail.dev ladder; copy-paste of a permissive seed beats a dependency.
- `.claude/CLAUDE.md`: never run `/gsd-profile-user`.

## Summary

Phase 1 is almost entirely a **port of the owner's sibling muhtari at `952fce9701175c291f4dab78d26205172cc29d8d`** (the commit that published muhtari 0.1.0 after its own phase 1, 21 plans), renamed and re-shaped from the Atari 7800 to the SMS/GG. All 126 non-planning files of that tree were fetched with `gh api` and read this session: presets, CMake, every test script, runner, libretro adapter, hosted RetroArch driver (241 lines), `ci.yml`, `release.yml`, `nightly.yml`, pins. The cogmaster repository already holds the renamed `scripts/` (`publish.sh` differs from the seed only in the archive name; `hygiene.sh` only in the ROM signature and names). What is **not** in the seed and must be designed here: (1) the much broader cogmaster API (D-10: `load`, `reset`, `get_frame`, `get_fault`, size-tagged in/out structs, 7 statuses) where muhtari has only 5 functions; (2) the internal state visitor, seeded instead from nesturbator `src/state.h`/`state.c` at `9f9386c661f6` (MIT, same owner); (3) RGB444 `uint16` frames with a crop rect instead of 8-bit indices; (4) four DEC/requirement deltas: rehearsal inside `ci.yml` and `CI required` (DEC.56, XFER-064; muhtari kept it in `release.yml`, not required), an install line that **verifies the checksum** (muhtari's does not), `--bench` that reports **max RSS itself** (muhtari measured RSS with `/usr/bin/time` in the nightly), and an **e2e line-budget test** (`policy.e2e_budget`, absent from the seed).

The biggest planning risks are not C code: they are the release rehearsal's move into `ci.yml` (signer-workflow pinning in `publish.sh verify`, reusable-workflow permission unions, merge-commit vs head SHA, Dependabot read-only tokens), byte-order of the `uint16` hash on `be32`, and the public header needing generated version macros while `version.txt` stays the single version source. The test inventory file `tests/inventory/ci.txt` is touched by nearly every plan, so plans are effectively sequential (XFER-066's parallel-wave rule applies only where inventories differ; `config.json` also has `parallelization: false`).

**Primary recommendation:** Port muhtari file by file (seed table below), in ~8 sequential plans, tracer first (header → test card → runner `--hash` with pinned SMS/GG hashes), then visitor/fault, runner completion, libretro, packaging/ABI gates, lanes and hygiene, workflows (with the rehearsal inside `ci.yml`), and a closing plan for measured timeouts and the owner's ruleset command. Add only the gates FRAME-01..09 and AGENTS rules name; every other check ENGINEERING lists becomes a seed.

### Pattern 1: Size-tagged structs with first-released size (D-11)
**What:** every boundary struct starts with `uint32_t size`; input below first-released size → `ERR_STRUCT_SIZE`; tail bytes beyond the library's `sizeof` must be zero; outputs copy `min(size, sizeof)`.
**When:** every public struct (config, versions, media, info, frame, run_result, fault).
**Source:** muhtari `src/instance.c` `muhtari__check_size` + `write_out`, with the 4096 cap so a garbage tag is refused without reading past the caller's object [VERIFIED: gh api muhtari@952fce97 `src/instance.c`]; nesturbator header comment adds "the caller zeroes the whole struct with memset" [VERIFIED: gh api nesturbator@9f9386c661f6 `include/nesturbator.h:13-23`]. `cogmaster_frame` is in/out: treat it as an input for the tag check and write only its output fields.

### Pattern 2: Exact inventory + JUnit completeness + negative controls
**What:** `cogmaster_add_test(NAME COMMAND LABELS TIMEOUT [COST])`; a deferred configure-time check compares registered `name<TAB>labels` with `tests/inventory/<preset>.txt` (sorted); after the test step, `check_junit.cmake` requires each selected name exactly once with `status="run"` and no `failure|error|skipped`; every gate `x` has `x.self_test` through `expect_fail.cmake -DCMD -DCODE -DREGEX`.
**Source:** muhtari `cmake/MuhtariTests.cmake`, `tests/cmake/check_junit.cmake`, `tests/cmake/expect_fail.cmake` [VERIFIED: gh api].
**Note for D-05:** implement the "wrong hash" negative control through `expect_fail.cmake`, not a bare `WILL_FAIL`: ENGINEERING §3 bans bare `WILL_FAIL` because it accepts a crash or a typo as success [CITED: ENGINEERING §3]. A `-P` hash-check script that fails with `hash mismatch` and a `.self_test` that passes a wrong constant and expects exit 1 with that regex keeps D-05's intent (a pinned-hash check with a negative control) and ENGINEERING's rule.

### Pattern 3: Version macros in the public header without a second version source
`release.single_version_source` (seed `tests/cmake/single_version.cmake`) fails when the version string appears in any tracked file other than `version.txt`, also at the next minor/patch (`.next`) [VERIFIED: gh api muhtari `tests/policy/tests.cmake`]. So `COGMASTER_VERSION_*` (D-10) must come from a **generated** header: `configure_file(cmake/version.h.in ${PROJECT_BINARY_DIR}/generated/cogmaster_version.h @ONLY)`, `include/cogmaster.h` does `#include "cogmaster_version.h"`, the generated dir is a `PUBLIC` `BUILD_INTERFACE` include, and `install(FILES …/cogmaster_version.h DESTINATION include COMPONENT library)`. muhtari kept its version header private, so this is new [ASSUMED design; see Open Question 1].

### Pattern 4: Test card as a pure function; crop hash serialised byte-wise
`testcard_pixel(x, y, machine)` returns `uint16_t` per D-15; `run_frame` fills the instance field; `get_frame` copies crop rows at the caller's pitch. The runner hashes `w*h` pixels as **LE bytes** (`lo = p & 0xFF, hi = p >> 8`), never `memcpy` of the `uint16_t` array (Pitfall 1).

### Pattern 5: libretro frame equality through a lossless palette
With `v * 0x11` per 4-bit channel, XRGB8888 → RGB444 is exactly `(r >> 4) | ((g >> 4) << 4) | ((b >> 4) << 8)`. The in-process host can rebuild the crop's LE `uint16` stream from the 60th video callback, hash it, and compare with the **same pinned constant** the runner test uses; that is "equals the runner's frame byte for byte" without a second rendering path. Keep muhtari's poison-and-compare loop (0xA5 per D-16) and both pixel formats (`cogmaster_libretro_rgb565` test-only module also covers the single-sample audio path) [VERIFIED: gh api muhtari `tests/libretro/tests.cmake`, `libretro/CMakeLists.txt`].

- `rehearsal` (needs `changes`, `build`; `if: github.event_name == 'pull_request' && !inputs.ref && head repo == this repo && release_inputs == 'true'`; permissions `contents: write, id-token: write, attestations: write`; `GH_TOKEN: github.token`): download `archives-*` and `hashes-*-*`, `publish.sh prepare`, `rehearsal-create`, `upload`, `actions/attest` with `subject-checksums`, `attested`, PATCH to prerelease `make_latest=false`, `verify`.

One README line beginning `mkdir -p ~/Library/Application` (the seed's `install_line.cmake` selects exactly one such line and swaps the release base for `BASE_URL`) [VERIFIED: gh api muhtari `tests/cmake/install_line.cmake`]:

## Common Pitfalls

### Pitfall 1: Byte order of the `uint16_t` frame hash
**What goes wrong:** `sha256_update(pixels, w*h*2)` hashes native-endian bytes, so `be32` (PowerPC under qemu) differs from the six LE legs.
**Why:** muhtari's frame was 8-bit, so it never met this [VERIFIED: muhtari `runner/main.c` hashes `uint8_t` bytes].
**How to avoid:** serialise each row to LE bytes in a small buffer, then hash; the same helper feeds the libretro test.
**Warning signs:** `hash-equality` fails only on `be32`.

### Pitfall 2: `c | c << 2` applied to the whole 6-bit value
**What goes wrong:** `expand(c)` must widen **each 2-bit channel** to 4 bits (`v | v << 2` per channel: 0, 5, 10, 15) and place them at `0000BBBBGGGGRRRR`; applying `c | c << 2` to the 6-bit word mixes channels.
**Source:** ARCHITECTURE §5 "SMS 6-bit CRAM expanded `c | c << 2` per channel" [VERIFIED: .planning/preparation/ARCHITECTURE.md:149].
**How to avoid:** `core.testcard.all_colours` asserts the SMS chart holds exactly the 64 values `{(b|b<<2)<<8 | (g|g<<2)<<4 | (r|r<<2)}`, and the GG chart exactly 4,096 distinct values, before any hash is pinned.

### Pitfall 3: Pinning a golden hash computed from a buggy card
**What goes wrong:** the pinned constant only proves "unchanged since pinning".
**How to avoid:** land the rule-level tests (corner, edge frame, bands, checker parity, grid lines, swatch count, magenta outside the GG window via `FULL_FIELD`) in the same plan, then pin the SMS and GG hashes printed by the runner; the cross-platform `hash-equality` then proves portability.

### Pitfall 4: `publish.sh verify` pins the signer to `release.yml`
**What goes wrong:** moving the rehearsal into `ci.yml` makes `actions/attest` sign as `ci.yml`; `verify` then fails at `gh attestation verify … --signer-workflow "$REPO/.github/workflows/release.yml"` [VERIFIED: scripts/publish.sh:122-125].
**How to avoid:** for `rehearsal-*` tags only, take the signer from `SIGNER_WORKFLOW` (default `release.yml`), keeping real releases pinned to `release.yml` (XFER-030); add a `policy.publish_ref`-style case that a release tag ignores the override.

### Pitfall 5: Reusable-workflow permission union
**What goes wrong:** `release.yml`'s `release-ci` job calls `ci.yml`; GitHub refuses to start a called workflow whose jobs request more than the caller grants (muhtari's comment on its `ci:` job) [VERIFIED: gh api muhtari `release.yml` comment]. Once `ci.yml` has a `rehearsal` job asking `contents: write, id-token: write, attestations: write`, the caller must grant that union even though the job is skipped there [ASSUMED: validation is static, not per `if`].
**How to avoid:** grant the union on `release-ci` (push to `main` only); keep the rehearsal's `if` false for `inputs.ref`.

### Pitfall 6: Which commit the rehearsal tags
**What goes wrong:** on `pull_request`, checkout defaults to the merge commit (`refs/pull/N/merge`), so `commit.txt` = merge SHA, while muhtari's rehearsal used `github.event.pull_request.head.sha` with `ci.yml` called at that ref [VERIFIED: gh api muhtari `release.yml`]. `publish.sh prepare` rejects a mismatch (`commit.txt files … records … not EXPECTED_SHA`).
**How to avoid:** inside `ci.yml` set `EXPECTED_SHA: ${{ github.sha }}` (the merge commit the legs built) and `SOURCE_REF: refs/pull/<n>/merge`. Whether GitHub accepts `target_commitish` = a merge-ref commit is [ASSUMED]; fallback: every job checks out `inputs.ref || github.event.pull_request.head.sha`.

### Pitfall 7: Dependabot PRs and a required rehearsal
**What goes wrong:** Dependabot action bumps edit `.github/workflows/ci.yml` (a release input), so the rehearsal runs with Dependabot's read-only `GITHUB_TOKEN` and fails, blocking every auto-merge [CITED: ENGINEERING §1 "Dependabot-triggered runs get a read-only GITHUB_TOKEN"].
**How to avoid:** defer Dependabot to the budgeted post-merge `ci:` PR (Open Question 5); when it lands, `release_inputs` is false for `github.actor == 'dependabot[bot]'`.

### Pitfall 8: The `.next` single-version check and docs
**What goes wrong:** any doc mentioning `0.1.0` fails `release.single_version_source.next` today, and any doc mentioning the current version fails once release-please writes it [VERIFIED: gh api muhtari `tests/policy/tests.cmake`].
**How to avoid:** README/docs never state a version number; `--version`, `.info` `display_version` and `get_versions` read it from `version.txt` through `configure_file`.

### Pitfall 9: The e2e budget has to count everything under `tests/retroarch/`
**What goes wrong:** muhtari's job keeps ~20 lines of inline shell (BMP byte flip) in `ci.yml`, outside any count [VERIFIED: gh api muhtari `ci.yml` "The compare's negative control"]. AGENTS rule 7 requires a test.
**How to avoid:** `policy.e2e_budget` (CMake `-P`) sums lines of every file under `tests/retroarch/` (≤ 300) with a self-test on a 301-line fixture; move the flip into `tests/retroarch/` (e.g. `flip.cmake`) so it is counted. Seed total today: 241.

### Pitfall 10: Stack size and helpers on MSVC and wasm32
**What goes wrong:** a large local (e.g. a 256×192 `uint16_t` row buffer of 98 KB) emits `__chkstk` under MSVC (not in `abi.undefined`'s allowlist) and overflows wasm32's 64 KiB stack (muhtari's runner comment: "a 77,440-byte local would overflow a 64 KiB stack, as wasm32's is") [VERIFIED: gh api muhtari `runner/main.c`].
**How to avoid:** field buffer inside the instance (allocated at create/load), runner buffers on the heap.

### Pitfall 11: Inventory churn serialises plans
**What goes wrong:** two plans in one wave both edit `tests/inventory/ci.txt` (and `wasm32.txt`, which is ci.txt minus libretro) and conflict.
**How to avoid:** sequential waves; one plan owns each inventory edit; `wasm32.txt` updated in the same task as `ci.txt`.

### Pitfall 12: GG geometry through the libretro core
**What goes wrong:** with no content the adapter shows only SMS (D-17), so a "GG geometry" assertion has no input path unless a core option or content selects GG.
**How to avoid:** see Open Question 3; derive `av_info` from `cogmaster_get_info` so the code path is machine-generic either way.

### Pitfall 13: Statuses need real behaviour (D-09)
`ERR_NO_CONTENT` and `ERR_PROFILE_REJECTED` have no obvious phase-1 trigger. Proposed mapping (planner confirms): `run_frame`/`get_frame` before a successful `load` → `ERR_NO_CONTENT`; `media.machine` outside {AUTO, SMS2, GG} → `ERR_PROFILE_REJECTED`; non-NULL `image` or `image_size != 0` in phase 1 → `ERR_ARGUMENT`; `get_frame` pitch below `w*2` → `ERR_BUFFER_TOO_SMALL`; allocator NULL return → `ERR_NO_MEMORY`. ### Pitfall 14: Owner-only steps

## Code Examples

### Test-card pixel (values verbatim from D-15)
```c
/* Source: 01-CONTEXT.md D-15 (lines 103-124); RGB444 is 0000BBBBGGGGRRRR. */
#define WHITE 0x0FFFu
#define BLACK 0x0000u
#define RED 0x000Fu
#define GREEN 0x00F0u
#define BLUE 0x0F00u
#define MAGENTA 0x0F0Fu

/* One 2-bit SMS channel to 4 bits: v | v << 2 (ARCHITECTURE §5, per channel). */
static uint16_t expand(uint32_t c)
{
    uint32_t r = c & 3u, g = (c >> 2) & 3u, b = (c >> 4) & 3u;
    return (uint16_t)(((b | b << 2) << 8) | ((g | g << 2) << 4) | (r | r << 2));
}

static uint16_t sms_pixel(uint32_t x, uint32_t y)
{
    if (x < 8u && y < 8u) return WHITE;
    if (x == 0u || x == 255u || y == 0u || y == 191u) return WHITE;
    if (y < 32u) return RED;
    if (y >= 161u) return GREEN;
    if (x < 64u) return ((x ^ y) & 1u) ? WHITE : BLACK;
    if (x >= 193u) return BLUE;
    uint32_t lx = x - 64u, ly = y - 32u;
    if (lx % 16u == 0u || ly % 16u == 0u) return BLACK;
    uint32_t col = lx >> 4, row = ly >> 4;
    uint32_t r = col & 3u, g = row & 3u, b = ((row >> 2) << 1) | (col >> 2);
    return expand(b << 4 | g << 2 | r);
}
```
(GG follows D-15's rules 0–7 the same way; pixel `b << 8 | g << 4 | r`.)
