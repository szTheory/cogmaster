- Version macros: generated `cogmaster_version.h` from `cmake/version.h.in` via `configure_file`, included by
  `include/cogmaster.h`, installed beside it (RESEARCH Pattern 3). `version.txt` stays the single version source.

  `COGMASTER_STATUS_OK = 0`, `ERR_ARGUMENT = 1` (NULL pointer, unknown flag bits, a non-NULL image or a non-zero
  image_size in this release), `ERR_STRUCT_SIZE = 2` (size tag rule D-11), `ERR_NO_MEMORY = 3` (allocator returned
  NULL), `ERR_BUFFER_TOO_SMALL = 4` (`pitch_bytes` below `w * 2`), `ERR_NO_CONTENT = 5` (`run_frame` or
  `get_frame` before a successful `load`), `ERR_PROFILE_REJECTED = 6` (`media.machine` not in {AUTO, SMS2, GG}).
- D-05 says the wrong-hash negative control uses `WILL_FAIL`; DEC.50 and ENGINEERING §3 (settled earlier) ban bare
  `WILL_FAIL` because it accepts a crash as success. This plan realises D-05's intent (two pinned hashes plus a
  wrong-hash control) through `tests/cmake/expect_fail.cmake` with a required exit code and the `hash mismatch`
  message, which is strictly stronger. Recorded deviation, not a narrowing.
- Output-struct size rule (D-02 + D-11, one rule for every output struct, public and append-only once released):
  an output struct (`cogmaster_info`, `cogmaster_versions`, `cogmaster_run_result`, and `cogmaster_fault` from plan
  02) whose `size` is below its first-released size is ERR_STRUCT_SIZE and is left untouched (D-02 states this for
  the fault struct; this plan applies the same lower bound to every output struct so one helper serves all of
  them); any `size` at or above the first-released size, with no upper bound, gets min(size, sizeof) bytes written
  (D-11, ARCHITECTURE §4) and bytes past the library's sizeof are left as the caller set them. No output cap is
  added: the header is append-only, so loosening later stays compatible while tightening would not. One helper,
  `cogmaster__check_out_size`, applies it everywhere.
- Input-struct size rule (D-11 plus one recorded narrowing): input structs (`cogmaster_config`, `cogmaster_media`,
  `cogmaster_frame` for its tag check) follow D-11 (below the first-released size → ERR_STRUCT_SIZE; between
  first-released and current → missing fields read as zero; larger accepted only if every byte past the library's
  sizeof is zero) with one addition: a `size` above 4096 is ERR_STRUCT_SIZE. Reason: checking that the extra bytes
  are zero reads `size` bytes of the caller's object, so an unbounded garbage size tag would make the core read far
  past it; the cap bounds that read (AGENTS rule 4, bounded core). Tightening before the first release costs
  nothing, and loosening later stays compatible. Deliberate narrowing of D-11, recorded here, in
  `docs/embedding.md` (Task 3) and in the ARCHITECTURE §4 size-tag row (amended by plan 12).
- File count (scope note): Task 1 lists 24 files because the tracer must touch every layer once (build, header,
  core, runner, harness, inventory); 15 of them are near-verbatim seed copies (renames only). Splitting the tracer
  would leave a first plan with no end-to-end path, which is the property the tracer exists to prove.
- Independent oracle: both pinned hashes were computed at planning by a separate script straight from the D-15
  rules (SMS e14d77ce…57ae7, GG 7404ed4a…5e779; 64 SMS chart colours, 4,096 GG chart colours). If the C code

  output (RESEARCH Pitfall 3).
