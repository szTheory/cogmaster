# Phase 7: Saves survive a restart - Context

**Gathered:** 2026-11-10
**Status:** Ready for planning (adversarial pass applied: 7 blocking items fixed)

<domain>
## Phase Boundary

A Game Gear 93C46 game and a battery game keep progress across restarts in the runner and in RetroArch; saves survive a killed process; `.srm` interop is claimed only for layouts that were written by cogmaster or measured. Requirements SAVE-01 to SAVE-06. Method: three role-lens advisors (EEPROM device, interop/libretro, durability/hosted) plus an adversarial pass. Sources: Microchip 93XX46 datasheet (primary), MAME BSD-3 `sega8` EEPROM board and `eepromser.cpp` at pin 1d7a454ed79e via `gh api` only; no GPL/LGPL source, and no GPGX/Gearsystem source (released binaries only).

<decisions>
## Implementation Decisions

### The 93C46 device (SAVE-01, SAVE-02)
- Model written from the datasheet, not ported from MAME. Commands: start bit, 2 opcode bits, 6 bits; READ (25 clocks, dummy 0 then D15..D0, sequential wrap at 64 words), EWEN, EWDS, WRITE (auto-erase), WRAL (overwrite after auto-erase; do NOT copy MAME's AND), ERASE, ERAL. Powers up write-disabled; READ ignores the latch; CS low resets the command logic; activity before a start bit is ignored.
- Option A: ready is immediate (DO high except while a READ shifts data); no busy timer. Option B (a tick-counted busy) is out of scope and deferred until a real cart hangs under A. `docs/saves.md` states the wiring and chip model are unverified on real hardware (they follow the datasheet and the pinned MAME board); the 7 EEPROM rows stay unclaimed in the ledger.
- Cartridge wiring per the pinned MAME sega8 EEPROM board (cited in code comments): `$FFFC` bit 3 opens the window at exactly `$8000` (all other reads stay ROM, first 1 KiB fixed); bit 7 resets the chip (drops CS, clears shift state, re-locks writes); a window write sets DI from b0, CLK from b1, CS from b2 (apply DI, then CS, then CLK); a window read returns `(last_written & 0xFC) | 0x02 | DO`. Words are little-endian; erased value all ones; image 128 bytes in `cart.ram` so battery span, generation counter, runner and libretro need no special case; one helper owns byte order.
- Generation counter moves once per completed command that changes bytes (compare bytes), never per clock edge or per WRAL byte; this is a new rule next to the "same-value write counts" rule for battery RAM and is documented in `docs/saves.md`.
- New board constant `COGMASTER_BOARD_SEGA_EEPROM = 10` (appended). The board owns BOTH its 16 KiB bank registers (Sega-style paging) and the `$8000` window in its own `mapper_ext.c` read/write arm behind `default:` (perf gate armed; no new branch on the hot Sega, Codemasters or ROM-only arms; no command function-pointer table: `abi.globals`). State `ctrl_max` for this board is 0x88 (bits 3 and 7) in `src/state.c` (today every non-Sega board gets 0), with a test that loads a state saved with the window open. Fix the `board >= KOREAN` test in `mapper_io`/state so this board does not visit `bank8`/`raw`; visit the eeprom fields with bounds (phase, count <= 8 in cmd, <= 16 in data and read; cross-check CS low implies idle and count 0). `struct cogmaster__eeprom` is about 7 bytes; hostile clocking is O(1) per write.
- The production core picks a board from the table, so the owned EEPROM fixture needs its own `tests/cart/fixture_facts.txt` row (declared 128, board 10) and `tools/cartdb.c` must validate it like the battery fixture's row (today hard-coded persistence 2, declared 32768, geometry 1); it counts as an eighth changed row in the table-equivalence check, and a fixture-identity test (as for the battery fixture) pins it. Generator: flip the `eeprom` slot to this board; emit persistence 2, geometry 1 and 128 bytes RAM for those 7 rows (today persistence 3 gets a zero-filled RAM which `battery.c` refuses); regenerate `src/cartdb.inc` and `tests/compat/catalog.tsv`; table equivalence must hold except those 7 rows. `cogmaster__battery_length` is generalised to the EEPROM kind (otherwise libretro reports 0 bytes and the save is silently lost).
- Versions: API 10 to 11, behaviour revision 12 to 13, state format 12 to 13 (same pattern as Phase 6); `abi.api_version` self-test and `tests/api/v11.c`.
- Tests: closed-form unit cases per command, power-up lock, WRITE refused before EWEN and after EWDS, READ wrap and sequential reads, generation counts over many clock edges and no bump on a same-data write, mid-command state round trip at every count of a WRITE and a READ, a ~60-line datasheet-written differential model on CS-framed random sequences (never unframed noise), `tests/fuzz/fuzz_eeprom.c` following `fuzz_run.c`, and one self-authored WLA-DX fixture `eeprom.asm` built like `tests/roms/src/battery.asm`: each run READs a counter word, increments it, then EWEN, WRITE, poll, READ-back, EWDS and a rejected WRITE, judged by the mailbox (a counter, so a second run differs from the first and the hosted control can prove the restart). State bounds are post-start-bit counts: command at most 8 more clocks, WRITE/WRAL data at most 16, READ at most 17 with the dummy bit. Existing games never enter the new arm: audio/frame pins untouched.

### `.srm` interop and import (SAVE-03, SAVE-04)
- SAVE-03 as written ("refuses others") conflicts with the shipped API 7 contract (battery import accepts any length 0..span and pads with FF). Decision: keep battery import exactly as shipped; EEPROM import accepts only 0 or exactly 128 bytes (a short prefix splits a word); never pad on export, never convert word order or trim silently; docs claim interop only for layouts that were written by cogmaster or measured and tested; REQUIREMENTS SAVE-03 and ROADMAP criterion 2 wording is amended to: "import refuses lengths over the span, EEPROM import accepts only 0 or 128 bytes, and the layouts of other cores are claimed only where measured" (testable with the length matrix).
- One-time measurement (a recorded command, never a committed harness; no ROM/save bytes committed): released Gearsystem (`gearsystem_mapper` option "EEPROM 93C46") with the phase's own EEPROM fixture, and released Genesis Plus GX with the owned `battery.sms`, each under the pinned RetroArch with the null-driver config, binaries pinned by SHA-256 of the buildbot zip; size from the core's reported save size, word order from the first bytes. A run that cannot elicit the path is recorded as `unmeasured`, never as a layout. If a path cannot be elicited the result is recorded as `unmeasured`; no owner ask by default. The buildbot zips are rolling, so rule 12 pins cannot apply: record the SHA-256 of the exact zip measured and the date, commit no re-fetch pin; a local run has no run URL, record the command and exit status only. Downloaded binaries are untrusted data: each in its own new empty directory, no execution from inside it beyond running the core through RetroArch.
- Import test: a table-driven length matrix {0, 1, 127, 128, 129, 8192, 16384, 32768} over boards {8 KB, 16 KB, 32 KB battery, EEPROM} with expected status and an unchanged-state check on every refusal; an EEPROM test imports a known `34 12` image and the guest reads 0x1234 (little-endian from the datasheet/MAME organisation, not from another core). Add the "oversize accepted when every byte past the span is FF" rule only if a measured core writes oversize files.
- libretro: flip `libretro_saves = "true"` together with the `host.c` guard test in the import/libretro plan (SAVE-04 must not depend on the hosted plan), and fix the `docs/saves.md` sentence that says it stays false; `repository.sh` already ties every "true" to a test. Guard test in `tests/libretro/host.c` per fixture: `retro_get_memory_size/data` for SAVE_RAM equal `cogmaster_get_battery` length and pointer (8 KB battery, 128 B EEPROM, plain cart NULL/0). Skip `SET_MEMORY_MAPS`. RetroArch decides how a differently sized `.srm` loads; only the runner can refuse foreign layouts.

### Runner durability and the hosted round trip (SAVE-05, SAVE-06)
- `--save-interval N` (integer 1..4294967295; 0 or absent is off, so existing hashes are untouched): after each frame's outputs call the existing flush when `n % N == 0` (it writes only if the generation changed and acknowledges only on success); a periodic failure exits 1 at once; the counter is frames, never wall time; `--frames` runs get no special case. SIGUSR1/SIGBREAK deferred (documented).
- Sweep: unify Windows temp names to `.tmp-<i>`; at save load unlink `<target>.tmp-0` .. `.tmp-1023` (exact pattern for this stem, no readdir, bounded, same on WASI; ignore a failed delete of a temp held open; simultaneous same-target writers remain unsupported and documented).
- POSIX directory sync after a successful rename: `open(dir, O_RDONLY|O_DIRECTORY)`, `fsync`, `close`; skipped under `__wasi__`; EINVAL/ENOTSUP tolerated, any other error is a failure that does not acknowledge the generation. Document macOS (fsync without F_FULLFSYNC; not added) and Windows (MoveFileExW same-volume metadata operation, no directory-sync analogue; keep MoveFileExW, avoid ReplaceFileW).
- Kill tests, deterministic on every lane through the existing `COGMASTER_SAVE_TEST` fault points (no real SIGKILL): the existing `COGMASTER_SAVE_INTERRUPT` fault (exits 93 after the temp is complete and before the replace) is reused for the kill case, and a new `COGMASTER_SAVE_DIRSYNC` fault is registered only where a directory sync exists (not `_WIN32`, not `__wasi__`); the test writes save A, runs a test build with `--save-interval 1 --frames 10` that exits 93 at the first periodic flush, asserts exit 93, no final frame line, a complete leftover temp and the target byte-equal to A, then a production run loads A and the temp is gone; the positive control (the periodic flush really replaced the file mid-run) uses a separate test-only "exit after replace k" fault or is dropped in favour of comparing against `cogmaster-run --frames k --save-dir` output. The existing `tests/runner/tests.cmake` case that pre-creates `round.trip.srm.tmp-0` and asserts it survives conflicts with the sweep: rewrite it (a different stem for the preserved-temporary case; the O_EXCL intent is testable only with a held-open file and is registered under `if(WIN32)` or `if(NOT WIN32)`, never `SKIP_RETURN_CODE`, which the repository check forbids).
- Hosted round trip (`tests/retroarch` stays at most 300 lines; 273 used): add a `KEEP` switch around `file(REMOVE_RECURSE RA_DIR)` in `run_retroarch.cmake` (1-2 lines); ci.yml steps use `cmake -P` and `cmake -E compare_files` (no stateful sh): for `battery.sms` and the EEPROM `.gg` fixture run the production-core RetroArch for about 30 frames, run again with `-DKEEP=1` (the restart), compare `ra/saves/<stem>.srm` to the `cogmaster-run --save-dir` oracle after each pass, plus a control that oracle pass 1 vs pass 2 differ through `expect_fail.cmake` (proves the second run read the first). If RetroArch writes no `.srm` on the `--max-frames` exit, raise `FRAMES` or have the fixture idle longer (`autosave_interval` is seconds and 30 null-driver frames last under a second); confirm on the first hosted run. Record the real `e2e_budget` number (the budget also counts the shared oracle; `wc -l tests/retroarch/*` alone shows 259). Re-derive that job's `timeout-minutes` from the first hosted run (rule from Phase 5). Upload retroarch.log only on failure. The EEPROM hosted case needs the board and fixture first.

### Process
- Plan order: (1) EEPROM device pure + closed-form/differential tests (no board); (2) board arm, generator flip, state/API 11/13, visitor fix, table equivalence; (3) fixture + fuzz; (4) runner durability (interval, sweep, dirsync, faults, kill tests); (5) import rules + `.srm` measurement record + docs + libretro guard; (6) hosted round trip + `.info` flip; (7) close: final hosted run, MAP-style proof that no existing pin moved, ship-time list. Each plan at most 10 files; at most 25 counted check-code lines for the phase (723 of 795 at last measurement; limit rises 1 per 10 src lines); docs within caps; no planning IDs in code or user docs; each gate a negative control and a "Fault prevented" line; MAME text only cited, `PROVENANCE.md` line if copied.
