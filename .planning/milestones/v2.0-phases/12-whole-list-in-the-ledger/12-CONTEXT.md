## Decisions

### D1. Row identity and population (LEDG-01)
- No format 3, no bridge, no `reason` column: every new row is a valid format-2 row (40-hex id, `boots@600`, default `cfg:`). The Phase 12 PR is judged by the OLD base judge (proof: D13).
- One default-profile row per sms/gg catalog identity (never SG-1000). Profile, computed once by the generator (D3): `machine` sms|gg; `region` japan iff the title holds `(Japan)` or a controller is a paddle (the core's rule, `cart.c:295-300`), else export; `tv` ntsc; `fm=on` iff japan and sms (Phase 11 default); `port1/port2` from the table codes (1 lphaser, 2 paddle, 3 sports, else pad) so a device title is never seeded as a pad row a pad run could satisfy (`compat.device_key`); `video` gg for gg, sms for sms. PAL and extra FM rows are not seeded: the library judge adds them (D8).
- **The 19 compound entries get a row keyed by `sha1("mame/<list>/<name>")`** (`<list>` in sms|gamegear, `<name>` the MAME software name). The orchestrator proposed the id `mame/<list>/<name>`; the base parser refuses it, so the PR would fail the base judge and force a format 3 and a `ci.yml` bridge. The derived id passes the old parser, is reproducible (`printf 'mame/sms/astropita' | sha1sum`; the test recomputes it with CMake `string(SHA1)` from the catalog `slot` field, so a C or endianness slip fails), and no dump can match it. The generator links `src/sha1.c` (reuse). The page says in one sentence that these ids are not image hashes.
- Counts: ledger data rows = 1,463 cart + 9 fixture = **1,472** (1,473 lines); sms 641 (629 + 12 compound), gg 822 (815 + 7). SG-1000 (214 records = 212 + 2 compound) is excluded and printed; the row-count test says "catalog identities", not "entries".

### D2. Status function and the closed reason vocabulary (LEDG-02)
First match wins (inputs: CC0 attributes and the slot table, seen only by the generator):
1. any record of the SHA-1 has `supported="no"` -> `skipped`, `mame_no` (6). The only mixed case, `excdizzy` (sms `no`, merged with gg `excdizzyp` `yes`), is `skipped`: the verdict is MAME's about this ROM and the conservative reading of a shared SHA-1 is the worst. `ar` and `sonicc630` follow the same rule; the text never says "does not work".
2. compound, no `no`: no `<rom>` -> `skipped` `no_rom` (1: mgear); `status="baddump"` -> `bad_dump` (2); more than one `<rom>` -> `multi_chip` (12); else `short_dump` (3).

Totals: 1,463 = 24 `skipped` (6 + 12 + 2 + 3 + 1) + 5 `unsupported` + 1,434 `unknown`.

The parser accepts any listed token, so a base ledger still parses after a retirement; `compat.reasons` and `compat.exit` require `open` for head rows.
- Runner exit 77 holds for board-0 rows because the table refuses the SHA-1 (`cart_fact_to_info` -> `UNSUPPORTED_BOARD`, `runner/main.c` `load_status` -> 77). `skipped` carries no exit claim: it is MAME's verdict; leaving it needs a pin bump (D7), never a recorded pass. ### D5. The ledger is written by `scripts/compat-seed.sh` (class `operation`) (LEDG-01)
- A script, not a `compat-common.sh` mode: the parser stays the only parser (about 20 counted lines saved). It is `operation` only because it writes the ledger and never judges; `compat.whole_list.fresh` asserts its output (it exits 1 on a stray id, so the reason is "writes, never judges"). It has no CSV reader: `normalize LEDGER` prints canonical rows in key order and `cases LEDGER` prints the same rows' fields (`compat_N_id`, `_machine`, `_region`, `_tv`, `_mapper`, `_status`, `_parameter`, `_config`) in the same order, so the script zips them to learn keys and statuses and copy rows verbatim.
- Rule (idempotent): copy fixture rows and every `pass`/`fail` row verbatim (never edit, drop or invent a digest); for each sms/gg catalog line generate the D1 default row: absent -> add with the seed date argument; present and `unknown|unsupported|skipped` -> refresh title, status, evidence from the catalog, keep the date when nothing changed; an `unknown|unsupported|skipped` row whose key no longer matches (a board arrived, the mapper re-keyed) is dropped and replaced; an id that is neither `fixture/` nor in the catalog exits 1. Output goes through `normalize`. It prints `compat-seed: identities=1463 rows=1472 unknown=1434 unsupported=5 skipped=24`.
- A board arrives: the slot gains a board in `tools/cartdb.c`, catalog and `cartdb.inc` regenerate, the token is marked `retired`, the seed re-keys the rows to `unknown`, the ratchet (D7) accepts exactly that, the library judge makes them `pass`/`fail`.
- `.gitattributes`: `linguist-generated=true` for `tests/compat/ledger.csv`, `catalog.tsv`, `pin-counts.txt` and `src/cartdb.inc` so the 1,462-line diff collapses in review (no release input).

### D6. Parser changes in `compat-common.sh` (counted, about +10) (LEDG-02, hardening)
- Reason rule (about 6 lines): for `unsupported`/`skipped`, `f[9]` must match `^reason=[a-z0-9_]+$` and the token must be a line of `COMPAT_REASONS`, loaded lazily on the first such row (literal-ledger tests pay nothing); failure is exit 2 `invalid ledger record N` in every mode, including the trusted judge once merged. One prelude line defaults `COMPAT_CATALOG=tests/compat/catalog.tsv` and `COMPAT_REASONS=tests/compat/reasons.txt` (cwd-relative; CI and library runs are at the repository root; tests pass stand-ins).
- Hardening (about 3 lines; octal byte escapes under `LC_ALL=C`, proven on BWK, mawk and gawk): refuse titles with the D3 format characters (`\342\200[\213-\217\252-\256]`, `\342\201[\246-\251]`, `\357\273\277`) or a first byte in `= + - @` (spoofing and formula injection).
- Row cap 4,096 -> **8,192** (`FNR>8193`). Worst case after a library run, bounded by the `update` key whitelist: 3 rows per SMS identity, 2 per GG (641 x 3 + 822 x 2 = 3,567, about 3,600 with device and fixture rows), 88 percent of the old cap; 8,192 is 2.3 times that and (about 300 bytes a row, 2.5 MB) fits the unchanged 4 MiB file cap (16,384 rows could not). The insertion sort is quadratic on unsorted input (BWK, reverse: 12.2 s at 8,000 rows); committed and generated ledgers are sorted, so only a hostile file pays. `allow.txt` stays 4,096 lines.
- `md()` also escapes `\ ` * _ ~ [ ] ( ) ! #` (numeric entities; an edit of the existing line). Real titles already hold `*`, `_`, `~`, `!`; hostile ones would become links or emphasis on a pin bump.
- `update` mode: loads the catalog `status` too and discards a candidate for an id whose status is not `unknown` (1 line; a catalog line with no status field reads as `unknown`, so five-field stand-in catalogs keep working): a library run can never turn `skipped` or `unsupported` into `pass`.
- Ratchet mode **fails closed**: an unreadable `COMPAT_CATALOG` or `COMPAT_REASONS` is exit 2 (a judge that silently skips R1/R3 is the fault); callers export absolute paths (D8) and tests run with `WORKING_DIRECTORY` set to the root or pass stand-ins.

### D7. Ratchet: three catalog-backed rules, no `ci.yml` edit (LEDG-03)
Added to `ratchet` mode (about +11 counted lines), reading the head catalog and `reasons.txt` through the D6 defaults (the CI step runs at the repository root, so the copied base judge sees head data):
- **R1 gate:** a head `pass`/`fail` row for an id whose head catalog `status` is `unsupported` or `skipped` exits 2. This is the whole of "`unsupported` -> `pass` once its board or device exists": the catalog stops saying `unsupported` only when the slot table gained a board.
- **R2 continuity:** a base row whose status is `fail`, `unsupported` or `skipped` keeps its id in the head ledger (any key) unless R3 releases it; `unknown` rows may vanish (the base rule protects only `pass` rows; hiding a `fail` by deleting it is the fault; the head tests, not the ratchet, guard the denominator, and a pin bump that drops an entry must not deadlock on the base judge).
- **R3 retirement:** a base `unsupported` row may change status or vanish (the mapper is in the key, so a re-key is a vanish) only if its token is `retired` in the head `reasons.txt` AND the head catalog status of its id is no longer `unsupported`; a base `skipped` row only if the head catalog status of its id is no longer `skipped` or the id is absent from the head catalog (a pin bump; `retired` is per token and `mame_no` covers six ids). Existing rules stay.
- **What ties the catalog to evidence (stated honestly).** Head catalog and `reasons.txt` are candidate data read by trusted code. For `unsupported` the tie is enforced: `compat.whole_list.reason` compares every sms/gg catalog line with `src/cartdb.inc` by SHA-1 (machine and board name equal the fact's; one awk, 1,656 lines, 0 differences today) and requires `unsupported` exactly for board 0, so a status cannot move without a slot-table change that `cart.database` runs against the core. For `skipped` (pin attributes, not in `cartdb.inc`) the only tie is `pin-counts.txt` (`mame_no 6`, compound 19): a hand edit must edit that file too and shows in review; the pinned re-run `cmp` of plan 1 and every pin bump re-proves it. The freshness tests (D5/D10) catch a hand-relabelled status.
- **The Phase 12 PR must flip nothing**: it adds new keys, changes no existing key's status, drops no id. The new rules govern the next PR and are proven by `compat.ratchet` (runs the candidate judge from `ROOT`) and the local base-judge run (D13).

The first loop already evaluates the seeded row with its own `cfg`, so the `unknown` default row flips through `compat-update.sh` and a missing PAL profile is added through the key whitelist. Device, `skipped` and `unsupported` rows keep their own `cfg` and are never re-derived. `library.sh` exports absolute `COMPAT_CATALOG` (`$COGMASTER_CATALOG`, else the tracked catalog) and `COMPAT_REASONS` (`$root/tests/compat/reasons.txt`) for its `update`, `ratchet` and `docs` calls (the owner may run from any directory).
- `library.synthetic`: the stand-in ledger is built by `compat-seed.sh` over its temporary catalog (fixture rows as the start), not a copy of the live ledger. Expectations: export-header image flips its row and adds one PAL row; Japan-header and GG images flip their one row; `rows_added=1` (it counts new lines; 4 before) with the flips asserted from the merged text. Controls: a `skipped` id's fact is discarded; a PAL row is still added when the default row is listed (the fault: a whole-list ledger that silently stops adoption). The merged ledger also goes through `compat.exit` (verdict `unmet`).
- `library.sh run` ends by printing the D10 `exit:` block (a failing command, including a tie failure, is printed, never a merge gate, rule 8). SEED-009: a `scan:` counts section only if it fits about 15 lines with a synthetic proof, else it stays in the seed. SEED-010/011 stay in their seeds.

### D9. The page: bounded by construction (LEDG-04)
- Order: intro (D11; says compound ids are not image hashes); counts (`Rows`, statuses, `unevaluated: unknown=N unsupported=M skipped=K`, pal rows judged, `fm=on` rows judged, predicate kinds, SG-1000 count from the catalog `sg` lines); `machine/mapper/status` groups (at most 60, then `+K more groups`); reason table `| token | status | rows |` (at most 32 lines); four row sections each ending `+K more ...` and a link to `tests/compat/ledger.csv`: fixtures (24), `unsupported` rows (20), `fail` rows (40), other evaluated rows (40, by key). `skipped` rows appear only in the reason table.

Worst row about 170 B.

### D10. The exit command and the flag/ledger tie: `tests/compat/exit.cmake`, test `compat.exit` (LEDG-05)
- `cmake -DLEDGER=tests/compat/ledger.csv -DINFO=libretro/cogmaster_libretro.info.in -P tests/compat/exit.cmake` (or `ctest --preset ci -R compat.exit -V`); class `behavior` (0 counted; row in `repository-checks.txt`, plan 7). Inputs: `normalize` output, catalog (`-DCATALOG`, default the tracked one), `reasons.txt`, `pin-counts.txt`, `quality.json` floors (`string(JSON)`, the `tests.ci` precedent). Legs (2) and (5) share one awk helper (an `include`) with `compat.whole_list.reason` and `.count`.
- **Claim-integrity legs (each names its fault, rule 7):** (1) `normalize` exits 0 (a ledger no parser reads); (2) every `unsupported`/`skipped` row has `reason=<open token>` (a silent refusal); (3) no fixture `fail`, no `infrastructure_error` (a red own proof or judge malfunction recorded as evidence); (4) fixture floors `compat.judged_pass >= 9`, `compat.pal_judged >= 1`, `compat.fm_judged >= 2` (today's values, re-measured at head); (5) cart identities equal the `pin-counts.txt` arithmetic (1,463) and the catalog's sms/gg count; (6) rows at most 50 percent of the parser cap.
- **Verdict leg: the owner's rule as a command.** A judged cart row is a `pass`/`fail` row whose id is a catalog sms/gg SHA-1 (not `fixture/`, not a derived compound id; R1 already refuses a judged `skipped` row). Floors in `quality.json`, each with a `reasons` entry: **`compat.cart_pass >= 20`** (judged cart `pass` rows), **`compat.cart_pal_judged >= 1`**, **`compat.cart_fm_judged >= 1`** (judged cart rows with `tv=pal`, `fm=on`). Why: they show a real library run reached the ledger; they are not a pass rate. 20 is about 1.4 percent of 1,444 images and over twice the 9 fixture passes, so fixtures plus a token run cannot reach it; agents cannot see the library's size, so a lower or higher number would be a guess and the floor is one reviewed `reasons` edit away from a change. `pass` only for the count, so boots `fail` profile facts cannot add to it; PAL and Japanese FM are the two profiles only a cart run adds (SEED-013), `judged` there because a `fail` still shows the profile ran. Today 0, 0, 0: **unmet**.
- **The tie (a test, so no human remembers):** with `-DINFO`, floors met requires `is_experimental` absent from `.info.in` (exit 1 `judged-cart floors met: remove is_experimental`) and floors unmet requires it present (exit 1 `is_experimental removed before the judged-cart floors are met`). An unmet verdict is not a failure: the committed ledger exits 0 with the flag present. `compat.exit` runs it on the committed ledger and the real `.info.in`, so the PR that merges the owner's rows is red until the flag and its wording go in that same PR (D11).
