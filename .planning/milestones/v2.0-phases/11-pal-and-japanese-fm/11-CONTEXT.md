## Decisions

### D1. Ledger format 2 (REG-01)
- Header `id,title,machine,region,tv,mapper,predicate,status,evidence,date` (10 columns; the header line is the version, no version column, no comment line). `region` is `export|japan`, `tv` is `ntsc|pal` (names mirror `COGMASTER_REGION_*`, `COGMASTER_TV_*`). No `any`, no `auto`: a row names the setting a run used, never a cartridge fact (Brazilian PAL-M and Argentine PAL-N are 262-line NTSC timing, SMS-SYSTEM section 1; no cart "is PAL"). `region` keeps its slot and `tv` follows it, Migration also rewrites each `cfg` to its explicit long form, quotes every field and re-sorts by the new key; it never touches a status, evidence text or date.
- `fm` is a resolved token in the `cfg:` prefix after `video`: `cfg:video=sms;fm=off;port1=pad;port2=pad;script=none;sha256=DIGEST/`. Values `on|off` only; `auto`, `1`, `ON`, empty are refused like the device tokens. Omitted resolves to `on` iff `region=japan` and `machine` is `sms` or `sms1`, else `off` (mirrors `instance.c:233-235`; `sg` and `gg` have no unit, and `sg` cannot run), so a legacy `ntsc-j` row becomes `fm=on`, which is what `--region ntsc-j` ran. `fm` in the cfg puts it in the key (`id|machine|region|tv|mapper|config|parameter`): rows differing only in `fm` are separate, and a `pass` under `fm=off` covers nothing under `fm=on`.
- Rejected at read time (exit 2 "invalid ledger record N"): `tv=pal` with `machine=gg` or `region=japan`; `fm=on` with `machine=gg`. These profiles cannot exist (the core refuses them by hardware fact, SMS-SYSTEM C6), so an `unsupported` row would lie; `unsupported` stays for boards and devices the core could gain. (Architecture wanted them accepted and judged `unsupported`; product, legal and the orchestrator wanted refusal: refusal chosen.) `fm=on` with `region=export` stays legal (owned-fixture controls; the judge never writes it).
- Format 1 stays readable as input only: `ntsc-u` and `any` read as export,ntsc; `ntsc-j` as japan,ntsc; `pal` as export,pal. A v2 file with a legacy token, a v1 file with a `tv` value, a 9-field row under the v2 header, a 10-field row under v1, and any unknown header exit 2.
- One parse, no copies: nine positional slots plus `tv`; one `emit()` writes the ten output fields for `normalize`, `results`, `update` (three loops share it today). `cases` additionally prints `compat_N_tv`, `_fm`, `_video`, `_port1`, `_port2`, `_script`, `_runner_region` (`ntsc-u|ntsc-j|pal`). `library.cmake:50` and `tests/compat/tests.cmake:50` drop their regexes and read these; `docs/conformance.md:55` states the grammar once.
- The committed ledger becomes the canonical long form `normalize` prints (explicit cfg with `fm=`); the 5 rows keep ids, predicates, statuses, evidence, dates. A status means what it meant before; `pass` for a PAL row means "ran under the 313-line profile with the predicate accepted", never "is a PAL release" or "right speed".

### D2. Migration is `normalize`; the proof uses literals (REG-01)
- Command: `sh scripts/compat-common.sh normalize tests/compat/ledger.csv > new && mv new tests/compat/ledger.csv`. No `migrate` mode. Normalizing v2 reproduces it byte for byte.
- `compat.migration` (new; `tests/compat/migration.cmake`, class `behavior`) embeds two literals: the 5-row v1 ledger as at v0.10.0 and its expected v2 form. Positive: `normalize(v1) == v2` byte for byte; `normalize(v2) == v2`; the multiset (id, machine, mapper, predicate-without-cfg, status, evidence, date) is equal before and after; the live `tests/compat/ledger.csv` has the v2 header and `normalize(live) == live`; those two live assertions are added in plan 4 (plan 3 leaves the ledger v1, so its test holds literals only). Literals are compared in memory, never through a file written with `file(WRITE)` (CRLF on Windows). The live file must not be compared with the literal: Phase 11's own rows and a legitimate `unknown` to `pass` on the CC0 row must stay possible. A synthetic legacy file (one row per old region token, `ntsc-j` with sms, with gg and with sg (`fm=off`), a quoted title, a device row) proves `ntsc-j` to japan,ntsc,`fm=on` (gg stays `fm=off`) and `pal` to export,pal, which no committed row exercises.
- Negative controls (exit 2): legacy token or `any` under v2; `region=pal`; `tv=ntsc-j`; pal with gg or japan; `fm=on` with gg; `fm=auto|ON|1|` (empty); a duplicate through omitted-versus-explicit default `fm`; 9 fields under v2, 10 under v1; unknown header. Preservation: the v2 literal with one status flipped, or one row dropped, fails the multiset check.
- `compat.ratchet` additions: `judge(base = v1 literal, head = v2 literal)` exits 0; exit 2 for: status changed, row dropped, a `pal` row migrated to `ntsc` (key vanishes), an `ntsc-j` row migrated with `fm=off` (identity changed), a pass value altered. Protected-pair loop gains `export,ntsc|export,pal` and `fm=off|fm=on`.
- One-time evidence on the real files, recorded as command and exit status (not a test), at plan 4 and again at plan 9 with the final ledger: `git show origin/main:tests/compat/ledger.csv > $TMP/v1.csv; sh scripts/compat-common.sh normalize $TMP/v1.csv | cmp - tests/compat/ledger.csv`.

### D5. `audio@F=H` in `--expect` (REG-03, runner half)
- Grammar `audio@<F>=<64 lowercase hex>`, F decimal 1..`--frames`; kind 4 in the same parser branch as `frame@` (sentinel moves to 5, hash validation shared). `audio@1=00` stays a usage error. Uppercase, 63 or 65 digits, `audio@0=`, `audio@600` (no value), `audio@600:$C200=00`, F above `--frames` exit 2.
- Meaning: SHA-256 of the merged transition stream of frames 1..F (records `tick u64 LE, source u8, level u16 LE`; per frame sorted by tick, source, emission index; last level per (tick, source); no-change levels dropped; memory persists across frames; power-on levels are tick-0 records; sources 0-3 PSG, 4 GG mask, 5 FM sum, 6 `$F2` byte; `runner/audio.c:75-137`). Equal to the `audio-transitions F count N sha256 H` line of `--frames F --hash-audio`. PCM is not a kind (the mix is provisional, DEC.36). The hash carries no profile bytes, so identity is in the ledger row (`psg_sweep` on `sms` and `gg-sms` ntsc-u share `d195b6d2...`).
- Mechanics: `cogmaster__audio_transitions_hex(const cogmaster__audio *, char hex[65])` copies the running SHA-256 context (plain data) and finalizes the copy, so one run holds several F. `main.c` sets `cfg.trace_records` and opens the audio object for `--hash-audio` or any audio case (today only `--hash-audio` enables the trace), calls `cogmaster__audio_frame` once per frame (the trace drains on read: one drain, never two consumers), prints the two `audio-` lines only with `--hash-audio`, and passes `const char *audio_hex` (NULL except at an audio frame) to `cogmaster__expect_frame`.
- Output `predicate kind=4 frame=F address=0000 pass|fail observed_audio=<hex> transitions=<count>` (matches the existing `predicate kind=` and `predicate.*pass` regexes). Exits: mismatch 3; dropped records, backward tick, sample-count violation 1; bad syntax 2. A script with `reset=1` plus an audio case exits 2 at load (ticks restart at a reset; today it would fail mid-run with 1). `--expect` still conflicts with `--boot bios --trace --mailbox --bench`.

### D7. Exact samples per frame (REG-02, runner half)
- Derivation: audio crystal 53,203,425 Hz = 12 x 4,433,618.75 (MAME `MASTER_CLOCK_PAL`; the 424/425 split against the reported rate 13,300,856/267,615 is 0.019 ppm, documented, not reopened). Per Z80 cycle at 48 kHz: NTSC 48,000 x 88 / 315,000,000 = 176/13,125; PAL 48,000 x 15 / 53,203,425 = 9,600/709,379 (709,379 x 75 = 53,203,425). Cycles per frame NTSC 179,208/3 = 59,736, PAL 214,092/3 = 71,364. Per frame NTSC 59,736 x 176/13,125 = 3,504,512/4,375; PAL 71,364 x 9,600/709,379 = 685,094,400/709,379 (both gcd 1; 801.0313 and 965.7664).
- `c(f) = floor(f x N / D)` in `uint64_t` (1e6 x 6.9e8 < 2^63); `n(f) = c(f) - c(f-1)`. PAL n(1..5) = 965, 966, 966, 966, 965. Recomputed: PAL c(1)=965, c(2)=1,931, c(50)=48,288, c(60)=57,945, c(300)=289,729, c(600)=579,459; NTSC c(60)=48,061, c(300)=240,309, c(600)=480,618.
- `hash_pcm` fails a frame unless `written == c(f) - c(f-1)` (replacing `frame_samples or +1`), exit 1, keeping the prefix `frame N holds M samples` (the small-cap test at `tests/runner/tests.cmake:1195` matches it) and adding the expected count. It runs under `--hash-audio` and any audio `--expect`. `docs/runner.md:150` gets the PAL closed form.
- `runner.audio_cadence` (new): for each TV and F in {1, 2, 3, 50, 60}, `--frames F --hash-audio` prints `audio-pcm ... samples S` equal to CMake `math(EXPR F*N/D)`; control: the same with N one lower fails (through `expect_fail.cmake`); the small-cap runner exits 1, not 3.

### D8. Fixture `vdp_vtable` (REG-02: V-counter tables)
- Owned WLA-DX `tests/roms/src/vdp_vtable.asm` + `.link`, three builds by `LINES_HEIGHT` 192/224/240 (as `vdp_lines`, `tests/fixtures/tests.cmake:397-410`); digests in `tests/built/expected.txt`, one comment line in `tests/roms/manifest.txt`, no image committed. Design: frame-interrupt synchronised start, interrupts off, then an exact 228-Z80-cycle loop (one line) reading `$7E` into `$C400+`. The iteration count comes from the TV verdict of the `ports.asm` `tv_sync`/`tv_count` routine (31-cycle frame loop), 313 or 262, reused rather than rewritten; any other verdict records count 0. One fixed read tick per line sees every table entry once per cycle, so records are rotation-invariant and need not model the read tick.

### D9. Fixture `pause_nmi` (REG-02: Pause at line 311)
- Hardware: /NMI is asserted on line `lines - 2` at tick 611: 260 NTSC, 311 PAL, every height; none on native Game Gear. That is the line before the last, where V reads `$FF` in every table (stepped at tick 604); MAME places it on the last line of the top border. Today only a white-box unit test covers it (`tests/bus/test_vdp.c:380-450`); every fixture's `$66` is `retn`, and `docs/conformance.md:368` says the Pause counter is "not in this fixture yet"; that sentence is updated.
- Owned `pause_nmi.asm` + `.link`, builds `pause_nmi_192/224/240`. IM 1; the frame-interrupt handler zeroes a 16-bit `n` at `$C300`; the main loop increments it in a fixed 31-cycle body; the `$66` handler reads `IN A,($7E)` to `$C310`, copies `n` to `$C311-2`, increments an NMI count at `$C314`, `retn`. Script `pause.input` (fixed-width `p1=00 p2=00 pause=B reset=0 start=0`, generated beside `play.input`): one edge held several frames (one NMI: the core is edge-triggered), later a second edge.
- Closed form, ticks from the frame interrupt (tick 607 of line H) to the NMI (tick 611 of line `lines-2`) = `(lines - 2 - H) x 684 + 4`: NTSC 192/224 = 46,516 / 24,628; PAL 192/224/240 = 81,400 / 59,512 / 48,568 (cycles: divide by 3). `n` lies in `[floor((C - 60) / 31), floor(C / 31)]` for C the cycle count (a band, like `h_at_frame_handler` `0033-003D`): PAL 192 about 875, NTSC 192 about 500; one line (228 cycles, about 7 iterations) is outside the band. The band edges are computed from the listing (interrupt latency at most one body plus the 13-cycle IM 1 accept, plus the handler's cycles before the store) as a CMake expression beside the constants; they may never be fitted to an observed run. Handler V value `$00FF`; NMI count 1 then 2; native GG profile expects 0.
- Tests: `fixtures.pause_nmi.mailbox.{ntsc,pal}.{192,224}`, `.pal.240`, `.gg`, `.judge.*`. Controls: the PAL image at `--region ntsc-u` fails the PAL band; a handler one line late would read `$00`, which the V record catches. Expected.csv source says "derived": no PAL logic-analyser capture exists (NTSC only, SYS.11).
